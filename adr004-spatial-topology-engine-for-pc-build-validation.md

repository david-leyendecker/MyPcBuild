# **ADR 004: Spatial Topology Engine for PC Build Validation**

## **Status**

Proposed

## **Context**

Our current compatibility engine relies on categorical matching (e.g., Socket, Form Factor). This is insufficient for:

1. Validating physical clearance in Small Form Factor (SFF) builds.  
2. Detecting inter-component interference (e.g., tall RAM modules hitting large air coolers).  
3. Providing data for a future 3D visual representation of the build.

The application uses a C\# backend with Domain-Driven Design (DDD), Marten for Event Sourcing, and follows the REPR pattern with HATEOAS for the REST API.

## **Decision**

We will implement a **3D Spatial Topology Engine** based on a recursive chamber-and-slot architecture.

### **1\. Domain Model**

We define the PC Case as a collection of **Chambers**. Each Chamber is a 3D bounding box that contains **Slots**.

* **Value Objects:** Vector3 and Dimensions (implemented as C\# records).  
* **Entities:** Part, Slot, and Chamber (implemented as C\# classes with private setters).  
* **Recursion:** A Part can provide its own SubSlots (e.g., a Motherboard provides CPU and RAM slots).

### **2\. Spatial Validation Logic**

Instead of property matching, compatibility is determined by:

* **Boundary Checks:** Ensuring a Part's dimensions \+ its Slot's global position do not exceed Chamber boundaries.  
* **Occupancy Checks:** Calculating Axis-Aligned Bounding Box (AABB) collisions between parts within the same coordinate space.  
* **Coordinate Flattening:** A domain service will resolve recursive slot positions into a single "Chamber Global" coordinate system.

### **3\. Event Sourcing (Marten)**

Changes to the topology will be captured as granular events:

* PartInstalledInSlot(BuildId, ChamberName, SlotId, PartId)  
* PartRemovedFromSlot(BuildId, SlotId)

### **4\. API (REPR \+ HATEOAS)**

Each topology action is a focused REPR endpoint. Responses will include HATEOAS links (rel) to guide the client through the build tree.

### **5\. Extendability for Complex Geometries**

While the initial implementation uses simple AABB (box) dimensions, the architecture is designed to support more complex definitions (e.g., for asymmetric air coolers or L-shaped components):

* **Composite Dimensions:** The Dimensions type can be extended to a composite pattern where a single Part occupies multiple bounding boxes relative to its origin.  
* **Exclusion Zones:** Future iterations can define "keep-out" zones within a part's volume to allow for specific clearances (like RAM slots under a cooler) without needing to hardcode "RAM Clearance" as a separate property.

## **Rejected Alternatives**

### **1\. Physics Engine Integration (e.g., PhysX, Bullet)**

* **Reason for Rejection:** Integrating a full physics engine adds significant overhead. A custom geometric service is more performant and easier to unit test within a DDD domain.

### **2\. Metadata "Max-Length" Flags**

* **Reason for Rejection:** Fails in modular cases where moving one part changes available space for another. Spatial topology allows limits to be calculated dynamically.

### **3\. Client-Side Only Validation**

* **Reason for Rejection:** The "Source of Truth" must reside in the backend to ensure build integrity before saving configurations or proceeding to checkout.

## **Consequences**

### **Pros**

* **High Accuracy:** Enables physical validation that simple category checks miss.  
* **Visual-Ready:** Data structure is 1:1 compatible with 3D engines like Three.js.  
* **Future-Proof:** The recursive slot and composite dimension strategy allows for highly detailed fitment checks as the database grows.  
* **Self-Describing:** HATEOAS decouples the frontend from the specific slot-tree logic.

### **Cons**

* **Data Density:** Requires high-quality dimensional data for all components.  
* **Computational Complexity:** Recursive coordinate resolution is more intensive than flag matching.

## **Compliance & Validation**

* **Boundary Test:** (Slot.X \+ Part.L) \<= Chamber.L.  
* **Dependency Test:** A child part cannot exist without a valid parent part installation event.
